핸드오버는 누가, 언제, 왜 정하나

2026. 10. 2 · LG U+ (화웨이 장비 지역) 기준으로 정리한 공부 노트 · 부록
한 줄 요약
폰이 "옮길래!" 하고 정하는 게 아님. 폰은 주변 셀 세기를 재서 보고만 하고,
기지국이 정해진 규칙(이벤트 A1~A5)에 따라 "저 셀로 가" 하고 명령하는 구조.
→ 그래서 핸드오버 기준 = 기지국(=통신사·장비사) 설정값.

1순서부터

핸드오버는 4단계로 일어난다. 우리 앱이 보는 건 사실상 맨 끝 결과(셀 ID가 바뀜)뿐이라는 걸 기억!

2이벤트 = "언제 보고할지" 규칙

3GPP 표준(TS 36.331)에 이름이 정해져 있다. 외울 필요는 없고 "무엇과 무엇을 비교하냐"만 보면 됨.

이벤트쉬운 말주로 쓰는 곳
A1서빙이 기준선보다 좋아짐"이제 괜찮으니 다른 주파수 측정 그만"
A2서빙이 기준선보다 나빠짐"위험하니 다른 주파수도 재 봐" (밴드 변경의 시작)
A3이웃이 서빙보다 offset만큼 더 셈같은 주파수 핸드오버의 기본
A4이웃이 기준선보다 좋음다른 주파수·부하 분산
A5서빙은 기준1보다 나쁘고 동시에 이웃은 기준2보다 좋음다른 주파수 (커버리지)
B1다른 기술(5G NR) 셀이 기준선보다 좋음LTE에 5G 덧붙이기 (NSA)

+A1~A5 조건식 공부 (TS 36.331 5.5.4)

기호부터

기호뜻
Ms서빙 셀(지금 셀) 측정값 — 보정 없이 그대로
Mp기준 셀(PCell) 측정값 — A3·A5에서 이 이름. 보통 = 서빙이라고 생각
Mn이웃 셀(옆 셀) 측정값
Thresh기준선 (예: −110 dBm)
Hys히스테리시스 — 경계에서 들락날락 안 하게 두는 여유
OffA3 오프셋 — 옆 셀이 몇 dB 더 세야 하나
Ofn / Ofp주파수별 보정 (이웃 주파수 / 서빙 주파수)
Ocn / Ocp셀별 보정(CIO) — "이 셀로는 잘/덜 넘어가게" 손잡이
TTTTime To Trigger — 진입 조건이 이 시간 동안 계속 맞아야 보고
  • 측정값은 RSRP(dBm) 또는 RSRQ(dB) — 기지국이 고른다.
  • 전부 진입 조건이 TTT 동안 유지 → 폰이 보고.
  • 이탈 조건 = 진입에서 Hys 부호만 뒤집은 것 (경계에서 금방 안 풀리게).

A1 — 서빙이 기준선보다 좋아짐

진입: Ms − Hys > Thresh
이탈: Ms + Hys < Thresh

"지금 셀 충분히 좋아졌다" → 다른 주파수 측정 그만 (A2로 시작한 측정 끝내기).
예) Thresh −100, Hys 2 → 서빙이 −98 dBm보다 좋아야 진입.

A2 — 서빙이 기준선보다 나빠짐

진입: Ms + Hys < Thresh
이탈: Ms − Hys > Thresh

"지금 셀 위험" → 다른 주파수·다른 기술 측정 시작 = 밴드 변경의 첫 단계.
예) Thresh −110, Hys 2 → 서빙이 −112 dBm보다 나빠야 진입.
A1이랑 짝 — A2로 켜고 A1로 끈다

A3 — 이웃이 서빙보다 오프셋만큼 더 셈 ★ 핸드오버 기본

진입: Mn + Ofn + Ocn − Hys > Mp + Ofp + Ocp + Off
이탈: Mn + Ofn + Ocn + Hys < Mp + Ofp + Ocp + Off

옆 셀이 지금 셀보다 (Off + Hys)만큼 더 센 상태가 TTT 동안 → 보고.
기준선(Thresh)이 없다! 절대 세기 상관없이 "누가 더 세냐"만 보는 상대 비교.
쓰임: 같은 주파수 핸드오버 (섹터 이동 · 기지국 변경 대부분).
예) 보정 다 0, Off 1, Hys 1, TTT 320 ms → 옆 셀이 2 dB 이상 센 게 0.32초 이어지면 보고.

A4 — 이웃이 기준선보다 좋음

진입: Mn + Ofn + Ocn − Hys > Thresh
이탈: Mn + Ofn + Ocn + Hys < Thresh

서빙은 상관없고 "옆 셀이 그냥 충분히 좋다" → 다른 주파수로 보내기 · 부하 분산 · 서비스별 이동.
= "서빙 멀쩡해도 옆이 좋으면 보내자" 정책용.

A5 — 서빙은 기준1보다 나쁘고, 동시에 이웃은 기준2보다 좋음

진입: Mp + Hys < Thresh1  그리고  Mn + Ofn + Ocn − Hys > Thresh2
이탈: Mp − Hys > Thresh1  또는  Mn + Ofn + Ocn + Hys < Thresh2

"지금 셀 별로 + 옆 셀 쓸 만함" → 커버리지 때문에 다른 주파수로. A3보다 조심스러운 기준.
진입은 둘 다(AND), 이탈은 하나만(OR) 깨져도 끝.

한눈에

이벤트누구를 보나비교 대상한 줄
A1서빙기준선좋아짐 → 측정 그만
A2서빙기준선나빠짐 → 다른 주파수 재 봐
A3이웃 vs 서빙서로옆이 더 셈 → 옮겨
A4이웃기준선옆이 충분히 좋음
A5서빙 + 이웃기준선 2개서빙 나쁨 그리고 옆 좋음
외우는 법
A1·A2 = 서빙만 (1 좋아짐 / 2 나빠짐)
A3 = 둘을 서로 비교
A4 = 이웃만
A5 = A2 + A4 합친 것

Hys 부호: 진입 땐 항상 "조건 만족하기 더 어렵게" 붙는다.
→ 좋아짐 보는 건 빼고(−), 나빠짐 보는 건 더하고(+).

참고: A6(CA에서 이웃이 SCell보다 오프셋만큼 셈)도 있음. 다른 기술(5G NR 등)은 B1(= A4의 다른 기술 버전), B2(= A5의 다른 기술 버전). LG U+ 5G NSA에서 5G 덧붙일 때 쓰는 게 B1.

실제로는 이렇게 이어진다 (화웨이 다른 주파수 핸드오버)

같은 주파수끼리는 이 과정 없이 A3 하나로 바로 — 같은 주파수 셀은 폰이 늘 재고 있으니까.

근거: 3GPP TS 36.331 5.5.4절 (이벤트 A1~A6, B1·B2 진입/이탈 조건)

3제일 중요한 A3 자세히

표준 원문 식은 이렇게 생겼다 (진입 조건):

Mn + Ofn + Ocn − Hys  >  Mp + Ofp + Ocp + Off

겁먹지 말고 풀어 쓰면 →

이웃 셀 세기(Mn, 셀별 보정 Ocn 포함)가 지금 셀 세기(Mp)보다
Off(오프셋) + Hys(히스테리시스) 만큼 더 세고,
그 상태가 TTT(Time To Trigger) 동안 쭉 이어지면 → 폰이 "A3 떴어요" 보고 → 기지국이 핸드오버.

화웨이 장비에서는 이 이름으로 설정한다

업계에서 흔히 말하는 "보통 값"은 offset 3 dB · hysteresis 0 dB · TTT 320 ms 정도 (출처 ③).

4밴드(주파수)를 바꿀 때는 절차가 다르다

같은 주파수끼리는 A3 하나면 끝. 근데 다른 주파수로 가려면 폰이 그 주파수를 먼저 재 봐야 해서 순서가 길다:

서빙이 나빠짐 → A2 (다른 주파수 재 봐!) → 측정 → A3 / A4 / A5 만족하면 이동
도중에 서빙이 다시 좋아지면 → A1 (측정 그만)

화웨이 쪽 이름: InterFreqHoA1/A2ThdRSRP(RSRQ), InterFreqHoA4ThdRSRP, InterFreqHoA1A2Hyst … 대부분 QCI별로 따로 정할 수 있다.
→ 같은 셀에서도 통화 중이냐 데이터만 쓰냐에 따라 기준이 다를 수 있다는 뜻!

55G 표시는? (NSA)

LG U+ 5G는 NSA = LTE를 "앵커(닻)"로 잡고 5G를 옆에 덧붙이는 방식.

  • 폰은 항상 LTE 셀에 붙어 있음 → 우리가 센 핸드오버는 전부 LTE 앵커 핸드오버.
  • 5G를 붙일지는 B1 이벤트(5G 셀이 기준보다 세면)로 결정.
  • LTE 앵커가 바뀌면 붙어 있던 5G도 다시 붙여야 할 수 있음 → 순간 끊김 원인.

우리 앱은 5G 셀을 한 번도 못 잡았다 (is_5g_actual 0%) → 이 부분은 검증 불가.

6핑퐁은 왜 생기고 어떻게 막나

너무 빨리 옮기게 설정 (offset·hys 작음, TTT 짧음) → 경계에서 왔다 갔다 = 핑퐁↑
너무 늦게 옮기게 설정 (값 큼) → 신호 다 죽을 때까지 버팀 = 끊김(RLF)↑
→ 둘 사이 줄타기. 자동으로 맞추는 기능이 SON의 MRO(Mobility Robustness Optimization).

막는 손잡이: Hys(여유) · TTT(기다리기) · Ocn(셀별 보정) · 측정 필터.

① 옆 셀이 더 세지면, 실제로 곧 옮겨 가나? 대체로 그렇다

같은 주파수 이웃이 서빙보다 셌던 측정 뒤 10초 안에 진짜 핸드오버가 났는지 셌다.

→ 이웃이 셀수록 곧 옮겨 갈 확률이 31% → 71%로 계단처럼 올라간다. "옆 셀이 일정 이상 세지면 옮긴다"(A3 방향)와 맞는 모습.

→ 근데 +3 dB 넘게 셌는데도 10초 동안 안 옮긴 게 38%. 이유 후보: 그 이웃이 이웃 목록에 등록 안 됐거나, Ocn으로 불리하게 보정됐거나, 그 사이 다시 약해졌거나. (5초 간격이라 구분 불가)

② 옮기기 직전에 이미 "A3 조건"이었나? 확인 안 됨

옮겨 간 셀이 직전 측정의 이웃 목록에 있던 경우(67%)만 놓고, 옮겨 간 셀 − 당시 서빙을 봤다.

  • 중앙값 −5 dB (가운데 50%: −8 ~ −2 dB) → 3.4초 전엔 옮겨 간 셀이 오히려 약했다.
  • 화웨이 기본 offset(+1 dB) 이상이었던 건 11%뿐.
  • 차량 −4 dB · 지하철 −5 dB · 도보 −3 dB · 정지 −1 dB → 멈춰 있을수록 0 dB(조건)에 가까워진다.

→ 이건 "A3를 안 따른다"가 아니라 "3초 사이에 판이 뒤집힌다"로 읽는 게 맞다. 빨리 움직일수록 3초 전 값과 핸드오버 순간 값의 차이가 커지고, 멈춰 있는 정지 세션은 −1 dB로 거의 조건선에 붙어 있다.
덤으로, 안드로이드가 주는 이웃 RSRP는 폰이 기지국에 보고하는 필터된 값과 같지 않을 수 있다.

→ 리포트 그림 3·4("핸드오버 순간에도 서빙이 더 셌다", "제일 센 셀로 간 비율")가 애매하게 나온 것도 같은 이유.

→ 저대역(850M)으로는 신호가 나쁠 때(−92) 내려가고, 좋을 때(−80) 다시 올라온다. "멀리 가는 저대역은 구멍 메우기, 용량 큰 고대역은 신호 좋을 때"라는 전형적인 다른 주파수 운용(A2로 측정 시작 → A4/A5로 이동)과 맞는 그림.

→ 다만 전체로 보면 밴드 변경 직전 −87 dBm vs 같은 주파수 핸드오버 직전 −83 dBm으로 차이가 크지 않다. A2 기준선이 아주 낮게(예: −110) 잡혀 있었다면 더 나빠야 했을 것 → 기준선이 비교적 높거나, 부하 분산 같은 다른 이유도 섞였을 가능성. 55건이라 단정은 못 함.

④ 핑퐁·정지 중 핸드오버 작은 offset이면 그럴 법

  • 전체 핸드오버의 16%가 핑퐁 (30초 안에 직전 셀로 복귀).
  • 9/27 정지(실내, 19분)에서도 기지국이 10번 바뀜. 직전 여유 중앙값 −1 dB → 두 셀이 거의 같은 세기로 붙어 있었음.

→ offset이 화웨이 기본값처럼 1 dB 정도로 작으면, 세기가 비슷한 두 셀 사이에서는 페이딩만으로도 왔다 갔다 할 수 있다. 기본값을 그대로 쓴다는 증거는 아니고, "그래도 이상하지 않다" 수준.
